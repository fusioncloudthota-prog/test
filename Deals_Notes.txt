Deals Transaction Integration – Process Overview

1. Transaction Processing

All deal-related transactions, such as marketing payouts, deal payouts, deal deposits, and other deal activities, are initiated in the platform and processed in Oracle Fusion Cloud. Once the transactions are processed, the corresponding responses are communicated back to the platform.

The platform generates payloads for various activities, including:

Marketing payouts
Deal deposits
Deal transactions
Deal payouts
Other deal-related activities
Whenever an activity occurs in the platform, a corresponding payload is generated and sent for processing.

2. Transaction Classification

The payloads are classified into two main categories:

Transactions: Deal-related financial transactions.
Applications: Receipt applications, credit memo applications, and debit memo applications associated with their respective deals.
3. Integration Flow

The integration process follows these steps:

Integration endpoints are exposed to the platform, which sends transaction payloads to the appropriate endpoints.
Upon receiving a payload, the integration validates it against the defined schema specifications for transactions and applications.
Once validated, the request is processed and stored in a queue.
The queued payloads are pushed to Oracle Integration Cloud (OIC) for further processing.
The Dequeue Integration connects to the queue, retrieves the available transactions, and inserts them into Oracle Autonomous Transaction Processing (ATP) database tables.
The respective integrations retrieve valid transaction data from ATP, stage it, and process it in Oracle Fusion Cloud.
Once processing is completed, the corresponding responses are communicated back to the platform.
4. Transaction Processing Sequence

Transactions are processed in ascending order.

For example, consider a scenario in which both a deal revenue transaction and a deal deposit transaction are received.

The deal deposit transaction must be applied to the corresponding deal revenue transaction.
Both transactions are processed independently in Oracle Fusion Cloud.
Once processing is completed, the results are communicated back to the platform.
The platform applies the deal deposit to the corresponding deal revenue transaction.
Until the application is completed, both transactions remain independent.
5. Summary

The integration architecture enables deal-related transactions to flow from the platform through OIC and ATP into Oracle Fusion Cloud. It supports payload validation, queue-based processing, transaction staging, and response communication back to the platform.

The process also supports the application of deal deposits against their corresponding deal revenue transactions while maintaining independent transaction processing.
